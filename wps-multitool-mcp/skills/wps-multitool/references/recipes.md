# 长任务配方

跨多步的任务，先规划再动手。以下三例是本 MCP 里最常遇到的形态。

## 通则

1. **先探活**（`wps_common_status`），没有文档就先建/开
2. **先读后写**：动手之前先读一份现状（现有样式、现有目录、现有数据），
   照着现状改，不要凭想象写
3. **分批**：一次改几十处容易中途失败，前功尽弃。分批做，每批做完验证
4. **做完读回来**：写完不验证等于没做。至少读一次确认落位了
5. **破坏性动作前留快照**：让用户在 WPS 面板里存一份，MCP 侧没有撤销

## 配方一：整篇文档排版

目标：把一份论文/报告排成正式版式。

```
1. status                → 确认文档在、桥通
2. load_tool_group(word) → 加载文字组
3. 读现状                → 现有标题都是什么样式？有没有目录？页边距多少？
4. 套样式                → 正文套"正文"样式，标题按级别套"标题 1/2/3"
5. 插目录                → 按标题级别生成（不要用重建版，会覆盖）
6. 页眉页脚 + 页码       → 页码类工具
7. 存快照 / 存盘
8. 读回验证              → 抽查几段，确认样式落位、目录条目数对得上
```

坑：
- **别用重建目录**，用户手改过的目录字段会被冲掉
- 标题层级要连续。跳级（标题 1 直接到标题 3）会导致目录层级乱
- 套样式**替换**直接格式会让用户的加粗/颜色丢失，动手前说一声

## 配方二：表格数据处理

目标：一份数据表要算指标、套格式、做成图。

```
1. status + 打开工作簿
2. load_tool_group(excel)
3. 读现状                → 先读表头与前几行，确认数据范围和类型
4. 写公式 / 批量写区域   → 公式优先于算好的值（用户改数据后能自动更新）
5. 格式化                → 数字格式、条件格式、列宽
6. 建图                  → 图表类工具
7. 存盘
8. 读回验证              → 重读公式结果，确认没出现 #REF! / #DIV/0!
```

坑：
- **批量写区域前先确认范围**。写超了会覆盖旁边的数据，且无法撤销
- 公式用相对引用还是绝对引用要想清楚；整列套公式会拖慢 WPS
- 表头行通常要冻结，用户没说也要做（可逆、体验提升明显）

## 配方三：做演示

```
1. status + 确认演示文稿已打开
2. load_tool_group(ppt)
3. 读现状                → 现有几张幻灯片、什么版式、有没有母版
4. 定结构                → 先说清楚要几页、每页讲什么，再动手
5. 逐页填内容            → 一次一页，每页填完读回来看
6. 统一样式              → 配色 / 母版 / 字体一次定好，不要逐页微调
7. 动画（可选）
8. 存盘
```

坑：
- **PPT 组个别工具只有静态校验**（组级台账记 `static`：矩阵里 5 条有据跳过）。
  每一步做完都要读回来看，并按 `wps_search_tools` 返回的 `verified` 字段如实告诉用户
  「这个工具只做过静态校验」——别笼统说「PPT 没验证过」，那是错的；也别因为它跑通了就当全部都验过。
- 母版和单页样式冲突时，母版优先；逐页设的背景会被母版覆盖
- 加动画前先想清楚会不会让阅读变慢，不是每个元素都该动

## 配方四：批量改格式

```
1. 读现状 → 搞清楚要改多少处、改完什么样
2. 先改 2~3 处 → 读回验证
3. 满意了再批量           → 前 3 处没验证就全量跑，错了要全量回滚
```

这是最危险的一类任务：范围大、影响面广、没有撤销。
中途失败时，已改的部分留在那里，只能靠快照恢复。
