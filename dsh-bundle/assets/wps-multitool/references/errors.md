# 错误前缀与应对

工具失败时返回的文本以一个方括号前缀开头。**先读前缀，再读正文** ——
前缀决定了能不能重试，重放错了会写两遍。

## 能重试的（请求根本没执行）

| 前缀 | 典型正文 | 怎么办 |
|---|---|---|
| `[busy\|可重试·稍后退避]` | WPS 正忙（COM 拒绝调用） | 等一下再发，不要连发 |
| `[bridge_unavailable\|可重试·需先拉起桥]` | 桥进程没起来 | 先 `wps_common_status`，必要时 `wps_common_repair` |
| `[daemon_unavailable\|可重试·需先拉起桥]` | 桥客户端已关闭 | 同上 |
| `[app_not_running\|可重试·需先启动WPS]` | WPS 没开 | 让用户打开 WPS |
| `[cancelled\|可重试·排队中被取消]` | 请求还在排队就被撤了 | 可以直接重发 |

排队被取消的那类**一定是安全的**——请求从未写进 WPS。

## 不能重试的（可能已经执行了一半）

| 前缀 | 典型正文 | 怎么办 |
|---|---|---|
| `[timeout\|勿重试·可能已执行一半]` | 超过调用时限 | **先读回来看结果**（用读取类工具确认），确认没生效再重做 |
| `[com_error\|勿重试·可能已执行一半]` | COM 调用失败 / `RPC_E_CALL_REJECTED` | 同上；连续出现说明 WPS 弹了模态框 |
| `[invalid_params\|勿重试·先改参数]` | 参数不对 | 改参数，不是重试 |
| `[document_not_found\|勿重试·先打开文档]` | 没有活动文档 | 先建/开文档 |
| `[unsupported_operation\|勿重试·本机不支持该接口]` | WPS 版本没这个能力 | 换条路，别重试 |
| `[unknown\|勿重试·…]` | 没归类成功 | 按前缀给的原因处理；没有就当"可能已执行" |

**判据很简单**：请求有没有送到 WPS。送不到的可以重放，送到的先查状态。

## 三个反复出现的坑

### "没有活动文档"，但用户明明开着文件

WPS 里存在"空壳文档"：`Documents.Add()` 立刻返回，但文档还没真正建好，
此时取它会报没有活动文档。遇到这个：

1. 先 `wps_common_status` 看文档数是不是 0
2. 是 0 就新建；不是 0 却取不到，说明是空壳 → `wps_common_repair`

### 一串 `RPC_E_CALL_REJECTED`

这是 WPS 弹了对话框（有模态框在等）。COM 是单线程的，对话框不关，
后面所有调用都会被拒。

处理：告诉用户"请检查 WPS 窗口有没有对话框没关"，然后按 `[busy]` 的方式退避重试。

### 一直报桥不通，但 WPS 是开着的

桥和 WPS 是两回事。桥不通不代表 WPS 坏了。顺序：

1. `wps_common_status` — 看桥状态与端口
2. 桥起不来 → `wps_common_repair`
3. 端口被占 → 换 `WPS_BRIDGE_HTTP_PORT` 再试

## 取消

客户端发取消通知时：
- 请求还在**排队** → 直接撤，安全，可以重发
- 已经**在途**（写进 WPS 了）→ 只读动作允许"不等了"，写入动作**拒绝取消**

也就是说：写入类操作发取消是无效的，别指望它能打断。
