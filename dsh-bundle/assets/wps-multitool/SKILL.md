# 操作 WPS 的正确链路

MCP 提供了近 300 个工具（以 `tools/list` 与 `wps_search_tools` 为准），能力不缺；
缺的是**按什么顺序用**。本技能只管顺序和判断，
不重复工具清单（清单会过期，清单请走 `wps_search_tools`）。

## 什么时候用 / 不用

**用**：用户要动 WPS 里的文字、表格、演示 —— 读内容、改格式、加公式、套样式、
处理修订、插索引与交叉引用、调页眉页脚、做 PPT 版式与动画。

**不用**：
- 通用 Office 问答（"Word 怎么插入页码"这种知识性问题，不需要碰 WPS）
- 代码任务、Excel 公式语法解释
- 非 WPS 的格式问题（pdf、md、docx 用别的工具）

## 五步主链路

按顺序走，不要跳步。跳步是本 MCP 最常见的失败原因。

### 1. 探活

先 `wps_common_status`。它会告诉你桥进程通不通、WPS 在不在、有没有活动文档。

三态分别对应三种处理，不要混：

| 状态 | 下一步 |
|---|---|
| 桥不通 | `wps_common_repair`，修完再探一次 |
| WPS 没开 | 让用户先打开 WPS，或你用建文档类工具打开 |
| 没有活动文档 | 必须先建/开文档，否则后续全部失败 |

### 2. 定组

`wps_route_intent` 把用户诉求映射到组：`word` / `excel` / `ppt` / `common`。
它用的是关键词打分，组间语义差别大时准确；表述含糊时**别硬猜**——去第 4 步搜。

### 3. 加载组

默认只列出 40 个基础工具，其余组要显式加载：`wps_load_tool_group`。

**"工具不存在"通常不是没有这个能力，是组没加载。** 先搜再加载，别直接告诉用户做不到。

### 4. 选型（必读反例）

`wps_search_tools` 可以直接用中文关键词（"插入表格""批注""改背景"）。

返回结果里的 **`notFor` 必须读**。本 MCP 有一批近名工具，光看名字分不出来：

- 6 个 `background`（纯色 / 图片 / 渐变 / 母版 / 图表区 / 全局）
- 5 个 `animation`（普通动画 / 预设 / 强调 / 顺序 / 清除）
- 2 个目录（页目录 vs 文档目录）、2 个缩放

选错不会报错，只会把事情改到别的地方去，用户还看不出来。

### 5. 写前确认

动文档之前做两件事：

1. **锁定目标**：用户可能开着多个文档。用切换文档类工具把目标钉死，
   否则切一次窗口就写到别的文件里去了。
2. **建快照**：COM 写入不是事务，没有撤销。现在有补偿手段了 ——
   - `wps_common_snapshot_create`：存一份磁盘副本，返回路径
   - `wps_common_batch` 检测到破坏性/非幂等步骤时会**自动**建，不用你操心
   - 改坏了用 `wps_common_snapshot_restore`；默认写出`.restored-<时间>`副本（不覆盖），
     要原地覆盖必须 `overwrite=true` + `confirm=true`，且**先关掉那个文档**（WPS 占着文件会 EBUSY）
   - 两个诚实点必须转述给用户：从未保存过的文档建不了快照（会报 `[勿重试·先另存为]`）；
     有未保存改动时，快照是**磁盘版本**，不含屏幕上还没存的内容

## 三条红线

### 一、`勿重试` 的错误绝不原样重放

工具失败时返回的前缀已经写明了能不能重试：

| 前缀 | 含义 | 该做什么 |
|---|---|---|
| `[可重试·…]` | 请求**没执行** | 可以重放，退避一下 |
| `[勿重试·可能已执行一半]` | 可能已经改了一半 | **先查状态**（读回来看结果），不要重放 |
| `[勿重试·先改参数]` | 参数不对 | 改参数，不是重试 |

超时和 COM 错误都属第二类。盲目重放 = 同一段内容写两遍、样式叠三层。

### 二、破坏性工具要跟用户确认

`tools/list` 里每个工具都带 `annotations`，其中 `destructiveHint: true` 的那批
会删内容、丢未保存改动、或原地转换格式（删除类、另存为、格式转换、关闭文档）。
执行前先说一句，别默默干。

`readOnlyHint: true` 的那批不会动文档 —— 但也意味着它**根本没生效**，
如果结果不对，别重复调用同一条，先怀疑前置步骤（没加载组、文档没打开、路径不对）。

### 三、PPT 的结果要复核

`wps_search_tools` 的结果里有 `verified` 字段：`live` = 真机跑通过，`static` = 只有静态校验。**这个字段仍然要读**——
PPT 组里还有没逐条验证的，读它才知道哪个工具要额外复核。

PPT 组的真值（照 `scripts/manual/tool-verification.json` 的 `ppt` 条目，别凭印象说）：

- 组级口径仍记 **`static`**：矩阵里仍有 5 条是**有据可查地跳过**的，不是漏跑；
- 但真机覆盖已经上量：PPT 组共 **100** 个工具，隔离验证矩阵 **103** 行（多出的行是旧名别名），
  实际执行 **98** 条、**全部跑通**，跳过的 **5** 条各有实测原因；
- 另有 **18** 个 PPT 工具在台账里逐条记为 `live`。

所以**别说「PPT 没验证过」**，也**别说「PPT 全部验证过了」**——两句都不准确。
真话是：绝大多数 PPT 工具跑过真机并有断言，个别几条因 WPS 侧限制或需人工介入而有据跳过。

`static` 不是「不能用」，是「没人在真机上验证过这一条」。用它做完事，要如实告诉用户
「这个工具只做过静态校验」，别把「没报错」当成「做对了」。
